【任务背景】
目前项目中日线和分钟线分别用 stock_daily / stock_minute 存储，更新逻辑在 data/jobs.py + data/updater.py + data/repository.py 中，数据来源主要是 data/pytdx_source.py。
我现在希望统一成一张表 stock_kline，通过 freq 字段区分不同周期（例如 "1d" / "60m" / "15m"），方便后续缠论和特征工程统一使用。
特别要求：

每个周期的数据时间起点要一致，即对于同一只股票，在配置的历史区间内，"1d"、"60m"、"15m" 这几个 freq 覆盖的交易日范围一致；

第一次全量更新时，要从配置的起始日期回补所有 freq；

之后增量更新时，要能“查出 stock_kline 里缺哪些交易日的数据，并补齐”。

任务 A：设计并创建 stock_kline，并迁移写入逻辑
A-1 表结构与索引

在数据库中新增一张表 stock_kline（PostgreSQL），字段建议如下（按现有项目风格实现）：

ts_code：string，例如 "SH.688122" / "SZ.000426"

freq：string，例如 "1d", "60m", "15m"

datetime：timestamp，K 线结束时间（分钟线用精确时间，日线用当日收盘时间或 00:00）

trade_date：date，datetime::date（方便按自然日扫描）

open, high, low, close：numeric

volume：bigint

amount：numeric（可选）

约束与索引：

唯一约束/主键：(ts_code, freq, datetime)

索引：

(ts_code, freq, trade_date)

如有必要，再加 (ts_code, freq, datetime DESC) 方便取最后一根

注意：不要删除现有 stock_daily / stock_minute，先保留兼容，后面再逐步迁移。

任务 B：统一更新逻辑，保证各个周期的起点一致

核心目标：

对于每一个 ts_code，在一个配置好的“历史区间”内（例如最近 500 个交易日）

freq="1d" 的日线覆盖整个区间；

每个分钟周期（例如 "60m", "15m"）在 同样的交易日集合 上都有数据（每个交易日至少要有一根 K）。

B-1 新增配置项

在项目配置中（例如 config.py 或 data/jobs 的顶部），新增两类参数：

KLINE_FREQS = ["1d", "60m", "15m"]
KLINE_HISTORY_DAYS = 500  # 或者一个日期 KLINE_START_DATE = date(2020,1,1)


你可以任选一种表达方式，要求是：

能明确一个“历史起点”：比如 today - KLINE_HISTORY_DAYS；

之后所有 freq 都以这个起点为下限，保证覆盖范围一致。

B-2 Updater 层：新增统一的 update 函数

def update_kline_for_universe(
    trade_date: date,

    要求：
      - 第一次运行时，从 trade_date 往前 history_days 天起补齐所有 freq
      - 之后每天运行时，只补齐缺失的部分
    """


建议实现逻辑：

从 data/basic_universe.get_basic_universe() 获取当前股票池（ts_code 列表）；

对每个 ts_code、每个 freq：

计算本次目标覆盖区间 [start_date_target, trade_date]：
start_date_target = trade_date - history_days；

查询 stock_kline 中当前 ts_code+freq 的覆盖区间（见任务 C）；

推导“缺失时间段”（例如完全没有数据 / 只有最近一段 / 中间有缺口）；

调用 PytdxDataSource.get_kline(ts_code, freq, start=missing_start, end=missing_end, ...) 拉数据，
再交给 upsert_stock_kline 写入。

要求：

逻辑上能覆盖“第一次全量 + 后续增量”；

不要求把“中间有缺口”的情况做得很复杂，至少要能处理“没有数据时全量补齐”和“有数据时从 last_date 往后补”。
